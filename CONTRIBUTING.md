# Contributing

## Setup

The package depends on `ark4ne/openapi-writer`, which is not on Packagist yet: clone it next to this repository
(`../openapi-writer`), then:

```bash
composer install
```

The design is documented (in French) in [`docs/architecture.md`](docs/architecture.md): read it before writing code.
In short, the generator **observes** the application, produces a neutral **description**, **passes** complete it,
and `ark4ne/openapi-writer` **writes** the document. Code that builds OpenAPI objects follows the writer's agent
skill (`skills/openapi-writer/` in the writer package).

## Checks

Every check below runs in the CI on each push and pull request.

| Command | What it does |
| --- | --- |
| `composer test` | Runs the whole PHPUnit suite |
| `composer test:coverage` | Runs the tests with coverage (pcov or Xdebug) and fails under 90% of lines |
| `composer stan` | PHPStan at max level with Larastan, the `phpat` architecture rules and the disallowed calls |
| `composer cs` / `composer cs:fix` | Checks / fixes the code style (PER-CS) |
| `composer mutation` | Mutation testing, minimum 80% MSI (needs `infection` installed globally) |
| `composer progress` | Rebuilds the progress table of `docs/README.md` from the epic checklists |
| `composer fixtures:update` | Rewrites the expected documents of the Feature scenarios: review the diff |
| `composer ci` | Every blocking check except coverage and mutation |

## Workflow

Each epic goes through the same cycle: contract (signatures and PHPDoc, neutral bodies), red tests, implementation.
Never add behaviour without a test that fails before it.

- Test names are sentences: `test_max_rule_on_string_sets_max_length`.
- Incomplete, skipped or risky tests, warnings, notices and deprecations fail the build.
- Every document generated by a Feature scenario is validated against the official schema of its version.

## Test suites

| Suite | Folder | Purpose |
| --- | --- | --- |
| Unit | `tests/Unit` | One test per rule mapper, extractor, sampler, pass and strategy |
| Feature | `tests/Feature` | Orchestra Testbench scenarios with their fixture app and expected documents |

Architecture tests (`tests/Architecture`, `phpat`) run with PHPStan.

## Roadmap

The roadmap lives in [`docs/`](docs/README.md) (written in French): one document per epic (E0 → E11) with its
checklist. When a deliverable is done, tick it in its epic document, run `composer progress`, and commit both files:
the CI fails when the progress table is out of date.
